让每一次遛狗
都算数。 Make every dog walk count.

Vitail 是一款遛狗记录与激励应用：用真实 GPS 记录每次散步的距离，按规则换算成积分，再到合作咖啡馆兑换咖啡和狗零食。目标是用轻量的游戏化，让主人养成规律遛狗的习惯。 Vitail tracks dog walks with real GPS, turns the distance into points under a fixed rule set, and lets owners redeem them for coffee and dog treats at partner cafés. Light gamification to build a daily walking habit.

下面是一段模拟散步：狗停下来闻了会儿东西，中途进了一段没信号的地方，还混进了几个漂移点。把所有点直接连起来会多算不少距离。点击播放，看过滤规则如何逐点处理；鼠标悬停查看每个点的判定原因。 A simulated walk: the dog stops to sniff, the signal drops for a stretch, and a few bad fixes slip in. 设计取舍：曾用 GPS 精度半径作为“最小移动距离”，结果每次更新要延迟 10–30 米。改为优先使用设备上报的速度判断静止，只保留 1.2 米的抖动下限，距离更新更跟手。 A trade-off: using the accuracy radius as the minimum step delayed updates by 10–30 m. Switching to the device's reported speed for stillness, with a 1.2 m jitter floor, made the distance feel live.

核心逻辑 · 积分规则Core logic · Points rules

奖励要有吸引力，也要有上限Rewards that motivate, with a ceiling

积分能换真实的咖啡，规则必须防刷又好理解。每天按当日累计 GPS 距离计分，同一天多次散步合并计算，跨天不叠加。拖动滑块试试。 Points buy real coffee, so the rules must resist farming and still be easy to grasp. Points come from the day's total GPS distance; walks on the same day add up, different days don't. Drag the slider.

数据与安全 · FirestoreData & security · Firestore

离线也能记，上云不会乱，改日期刷不了分Works offline, merges cleanly, can't be gamed by changing the date

遛狗常在信号差的公园里。每台手机记录自己当天走了多少（只增不减），云端按“设备 × 日期”保存各自的累计值。这样同一份数据上传两次不会翻倍，两台手机同时登录也不会互相覆盖。 Walks often happen in parks with weak signal. Each phone records how far it walked each day (it only grows), and the cloud keeps that running total per device per day. Uploading twice can't double it, and two signed-in phones never overwrite each other.

服务器时钟Server clock

只允许修改今天及前 2 天的记录，以服务器时间为准，改手机日期无法补录旧日子。Only today and the 2 days before can change, by the server's time, so editing the phone's date can't back-fill old days.

固定 ID 的奖励Fixed award IDs

每笔奖励是独立记录，如 goal:2026-10-22、streak:7，金额固定，无法重复或放大。Each award is its own record, like goal:2026-10-22 or streak:7, with a fixed amount, so it can't repeat or inflate.

兑换不透支No overspending

兑换价格必须与奖励表一致，余额不能为负；领取状态只能从 ready 变为 collected 一次。Claims must match the reward price and can't push the balance below zero; a claim moves from ready to collected once.

诚实的边界Known limit

规则无法判断 GPS 本身是否被伪造。这需要后端或 App Check，已记录为后续工作。The rules can't tell if the GPS itself is spoofed. That needs a backend or App Check, logged as future work.

工程实践Engineering

核心逻辑写成纯函数，再用测试钉住Core logic as pure functions, pinned down by tests

测距、积分、同步合并都与 UI 解耦，可以不启动 App 直接用 Node 测试运行器验证。真实设备上的问题，则针对性地做兼容处理。 Distance, points and sync merging are decoupled from the UI, so they run under Node's test runner without launching the app. Real-device issues got targeted fixes.
